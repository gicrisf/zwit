#+begin_description
Write AI coding assistant skills in Org mode and export them to SKILL.md.
#+end_description

Ox-Skills is an Org exporter backend that writes ~SKILL.md~ files with YAML frontmatter. It keeps prompt engineering in Org mode and exports directly into the directory an AI coding assistant scans for skills.

*** How it works

File-level ~SKILL_*~ keywords and ~EXPORT_SKILL_*~ property drawers describe the skill: name, description, allowed tools, argument hints, model, and output location. Source blocks marked ~:inject yes~ become executable context blocks that the harness runs at invocation time, while ordinary source blocks export as normal fenced code.

A single Org file can hold many skills, and ~EXPORT_SKILL_SUBDIR~ places them into nested directories. The Skills backend appears under ~s~ in the Org export dispatcher and can write the current file, a subtree, or all subtrees to ~SKILL.md~.

Start with [[/projects/ox-skills/getting-started/quick-start/][Quick Start]], then use the reference pages for keywords, injection, and multi-skill exports.

*** Real-world example

[[https://github.com/gicrisf/skills][gicrisf/skills]] is a collection of AI agent skills exported from Org mode with ox-skills. It demonstrates a multi-skill ~SKILLS.org~, the WIM export workflow, symlinks into tool skill directories, and a meta-skill for bootstrapping new skills.

#+begin_description
Create a first skill and export it to SKILL.md.
#+end_description

*** Write the skill

Set ~SKILL_BASE_DIR~ to the directory where skills should be written. Add the skill metadata as file-level keywords and write the body:

#+begin_src org
,#+SKILL_NAME: review
,#+SKILL_DESCRIPTION: Review code changes in the current branch
,#+SKILL_ALLOWED_TOOLS: Bash Read
,#+SKILL_USER_INVOCABLE: true
,#+SKILL_BASE_DIR: ~/.claude/skills

,* Instructions

Focus on correctness, not style. Check for edge cases.

,#+begin_src sh :inject yes
git diff HEAD
,#+end_src
#+end_src

*** Export

Run ~M-x org-export-dispatch~ (~C-c C-e~). The Skills backend appears under ~s~:

#+begin_example
 [s] Export to SKILL.md
     [s] File to SKILL.md
     [S] File to a temporary buffer
     [w] Subtree or File to SKILL.md
     [a] All subtrees (or File) to SKILL.md
#+end_example

The skill is written to ~{SKILL_BASE_DIR}/{SKILL_NAME}/SKILL.md~. In this example, that is =~/.claude/skills/review/SKILL.md=.

** Exporting Skills

#+begin_description
Use the export dispatcher and understand how WIM chooses a skill.
#+end_description

*** Export commands

The Skills backend is available under ~s~ in ~M-x org-export-dispatch~ (~C-c C-e~).

| Key | Action |
|-----+--------|
| ~s~ | Export the current file to SKILL.md |
| ~S~ | Export the current file to a temporary buffer |
| ~w~ | Export the current subtree or file to SKILL.md |
| ~a~ | Export all subtrees, or the current file, to SKILL.md |

~ox-skills-export-wim-to-md~ is the WIM command behind ~w~ and ~a~. It chooses what to export from point:

1. If the heading at point has ~EXPORT_SKILL_NAME~, export that subtree.
2. Otherwise walk up the heading hierarchy until a skill is found.
3. If no heading has ~EXPORT_SKILL_NAME~, export the whole file using the file-level ~SKILL_NAME~ keyword.

With a prefix argument (~C-u~), it exports every subtree in the buffer that has ~EXPORT_SKILL_NAME~.

*** Output path

Each exported skill is written to:

#+begin_example
{SKILL_BASE_DIR}/{EXPORT_SKILL_NAME}/SKILL.md
#+end_example

~SKILL_BASE_DIR~ is resolved in this order:

1. ~EXPORT_SKILL_BASE_DIR~ property on the subtree
2. File-level ~#+SKILL_BASE_DIR:~ keyword
3. ~ox-skills-default-base-dir~
4. Directory of the current Org file

*** Example

Given a multi-skill file:

#+begin_src org
,#+SKILL_BASE_DIR: ~/my-project

,* Skill One
:PROPERTIES:
:EXPORT_SKILL_NAME: skill-one
:END:

,** Setup

Some instructions here.

,* Skill Two
:PROPERTIES:
:EXPORT_SKILL_NAME: skill-two
:END:

Some other instructions.
#+end_src

| Point is at | ~ox-skills-export-wim-to-md~ | ~C-u ox-skills-export-wim-to-md~ |
|-------------+------------------------------+-----------------------------------|
| Setup subheading | exports Skill One | exports both skills |
| Skill One heading | exports Skill One | exports both skills |
| Skill Two heading | exports Skill Two | exports both skills |
| Before any heading | exports the whole file | exports both skills |

*** Other export commands

| Command | Behavior |
|---------+----------|
| ~ox-skills-export-to-md~ | Export the current buffer or subtree explicitly |
| ~ox-skills-export-as-md~ | Export to a temporary buffer |
| ~ox-skills-export-wim-to-md~ | Smart dispatch based on point, or all skills with ~C-u~ |

*** Supported fields

| Org keyword | YAML field | Type |
|-------------+------------+------|
| ~SKILL_NAME~ | ~name~ | string |
| ~SKILL_DESCRIPTION~ | ~description~ | string |
| ~SKILL_WHEN_TO_USE~ | ~when_to_use~ | string |
| ~SKILL_ARGUMENT_HINT~ | ~argument-hint~ | string |
| ~SKILL_ARGUMENTS~ | ~arguments~ | list |
| ~SKILL_ALLOWED_TOOLS~ | ~allowed-tools~ | list |
| ~SKILL_DISABLE_MODEL_INVOCATION~ | ~disable-model-invocation~ | bool |
| ~SKILL_USER_INVOCABLE~ | ~user-invocable~ | bool |
| ~SKILL_MODEL~ | ~model~ | string |
| ~SKILL_EFFORT~ | ~effort~ | string |
| ~SKILL_CONTEXT~ | ~context~ | string |
| ~SKILL_AGENT~ | ~agent~ | string |
| ~SKILL_PATHS~ | ~paths~ | list |
| ~SKILL_SHELL~ | ~shell~ | string |
| ~SKILL_BASE_DIR~ | output path only | — |

List fields are space-separated; quote multi-word items. Boolean fields accept =true= or =yes=, and =false= or =no=.

*** File-level and subtree metadata

File-level exports use ~#+SKILL_*~ keywords. Subtree exports use the same names in a ~:PROPERTIES:~ drawer with an ~EXPORT_~ prefix.

#+begin_src org
,* Review skill
:PROPERTIES:
:EXPORT_SKILL_NAME: review
:EXPORT_SKILL_DESCRIPTION: Review code changes
:EXPORT_SKILL_ALLOWED_TOOLS: Bash Read
:END:
#+end_src

#+begin_description
Inject fresh command output into a skill at invocation time.
#+end_description

Source blocks with ~:inject yes~ become executable context blocks. The harness runs them when the skill is invoked:

#+begin_src org
,#+begin_src sh :inject yes
git diff HEAD
,#+end_src
#+end_src

The exported ~SKILL.md~ contains:

#+begin_example
```!
git diff HEAD
```
#+end_example

Regular source blocks export as standard fenced code blocks.

#+begin_description
Keep multiple skills in one Org file and export them in one command.
#+end_description

Give each skill subtree an ~EXPORT_SKILL_NAME~ property and a shared ~SKILL_BASE_DIR~:

#+begin_src org
,#+SKILL_BASE_DIR: ~/.claude/skills

,* Review skill
:PROPERTIES:
:EXPORT_SKILL_NAME: review
:EXPORT_SKILL_DESCRIPTION: Review code changes
:EXPORT_SKILL_ALLOWED_TOOLS: Bash Read
:END:

...

,* Deploy skill
:PROPERTIES:
:EXPORT_SKILL_NAME: deploy
:EXPORT_SKILL_DESCRIPTION: Deploy to production
:END:

...
#+end_src

Run ~M-x ox-skills-export-wim-to-md~ (~C-c C-e s a~) to export all subtrees. This writes:

#+begin_example
~/.claude/skills/review/SKILL.md
~/.claude/skills/deploy/SKILL.md
#+end_example

Set ~SKILL_BASE_DIR~ to wherever the target tool expects skills. Ox-Skills writes directly into that directory; it does not append an extra subdirectory automatically.

** Subdirectories
:PROPERTIES:
  :EXPORT_FILE_NAME: subdirectories
  :EXPORT_ZOLA_SECTION: projects/ox-skills/reference
  :EXPORT_ZOLA_WEIGHT: 50
  :EXPORT_ZOLA_CUSTOM_FRONT_MATTER: :extra '((lead . "Place skills into nested directories with EXPORT_SKILL_SUBDIR.") (toc . true))
:END:

#+begin_description
Organize skills into nested directories with section properties.
#+end_description

Declare section headings with ~EXPORT_SKILL_SUBDIR~. Each ancestor contributes a path segment to skills nested below it:

#+begin_src org
,#+SKILL_BASE_DIR: ~/.claude/skills

,* Engineering
:PROPERTIES:
:EXPORT_SKILL_SUBDIR: engineering
:END:

,** Tools
:PROPERTIES:
:EXPORT_SKILL_SUBDIR: tools
:END:

,*** Code Review
:PROPERTIES:
:EXPORT_SKILL_NAME: code-review
:EXPORT_SKILL_DESCRIPTION: Review code changes
:END:
#+end_src

This produces:

#+begin_example
~/.claude/skills/
└── engineering/
    └── tools/
        └── code-review/
            └── SKILL.md
#+end_example

Section headings without ~EXPORT_SKILL_NAME~ are not exported themselves. They only contribute their ~EXPORT_SKILL_SUBDIR~ segment to nested skills. Sections can be nested to any depth.

Skill harnesses scan all subdirectories under the skills root, so a skill at ~engineering/tools/code-review/SKILL.md~ is discovered just like one at ~code-review/SKILL.md~.
