#+begin_description
A native command-line front end for the Ondine Mermaid compiler.
#+end_description

Ondine CLI is the native command-line front end for the Ondine compiler. It renders Mermaid diagrams to SVG or ASCII, and transforms Mermaid fences in Markdown into inline SVG in a separate output tree. The package is ~ondine-cli~; the installed binary is ~ondine~.

*** Why

The upstream Ondine toolchain runs through Node and npm. This front end keeps the same compiler and output but removes the Node startup and WebAssembly overhead: one native binary, no runtime, no network requests. It covers all 33 Ondine diagram types and fits into CI jobs, Makefiles, and static-site pipelines.

*** Advantages

- *Native:* One Rust binary. No Node.js or WebAssembly runtime is needed.
- *Fast:* Avoids Node startup and WebAssembly compilation.
- *Identical output:* Uses the same Ondine compiler and produces the same SVG.
- *Complete:* All 33 Ondine diagram types.
- *Markdown-aware:* Transforms fenced Mermaid blocks without modifying the source files.
- *Build-friendly:* Fits CI jobs, Makefiles, and static-site pipelines.

*** Performance

Native startup is a few milliseconds. The table compares ASCII output against ~ondine@0.0.3~:

| Workload                       |     Rust |      npm | Ratio |
|--------------------------------+----------+----------+-------|
| 522 diagrams, per-type batches |  0.292 s |  9.041 s |   31x |
| 522 diagrams, one process      |  0.136 s |  0.959 s |    7x |
| Per diagram, one process       | 0.261 ms | 1.836 ms |    7x |

*** Scope

This release renders SVG and ASCII, and transforms Markdown fences into a separate output tree. It does not edit Markdown in place, print terminal images, or produce JSON. ~--check~ verifies generated output. The compiler crate is pinned to a commit in ~wevm/ondine~ rather than a crates.io release, so compiler updates are deliberate.

Start with [[/projects/ondine-cli/getting-started/quick-start/][Quick Start]], then read [[/projects/ondine-cli/reference/markdown-fences/][Markdown Fences]] for the full transformation behavior.

#+begin_description
Install ondine, render a diagram, and transform a Markdown tree.
#+end_description

*** Requirements

You need Linux ~x86_64~ for the prebuilt binary, or Rust 1.97.0 or newer to build from source. Ondine CLI has no Node.js, npm, or WebAssembly runtime dependency.

*** Install

#+begin_src sh
curl -fsSL https://raw.githubusercontent.com/gicrisf/ondine-cli/main/install.sh | bash
#+end_src

The installer places ~ondine~ in =~/.local/bin=. See [[/projects/ondine-cli/getting-started/installation/][Installation]] for manual downloads and other installation options.

*** Render a diagram

Write Mermaid source in ~flow.mmd~:

#+begin_src text
flowchart LR
  A[Input] --> B[SVG]
#+end_src

Render it beside the source file:

#+begin_src sh
ondine flow.mmd
#+end_src

This writes ~flow.svg~. To render standard input:

#+begin_src sh
cat flow.mmd | ondine > flow.svg
#+end_src

To print the diagram as ASCII text instead:

#+begin_src sh
ondine --ascii flow.mmd
#+end_src

*** Transform Markdown fences

Put a Mermaid fence in Markdown:

#+begin_src markdown
```mermaid
flowchart LR
  A --> B
```
#+end_src

Transform the Markdown tree without modifying the source:

#+begin_src sh
ondine markdown content --out-dir build/content
#+end_src

The output mirrors the input tree. Check that generated files are current:

#+begin_src sh
ondine markdown content --out-dir build/content --check
#+end_src

See [[/projects/ondine-cli/reference/markdown-fences/][Markdown Fences]] for the full behavior.

#+begin_description
Install ondine with the prebuilt installer, Cargo, or Nix.

*** Requirements

The prebuilt binary targets ~x86_64-unknown-linux-musl~. Building from source requires Rust 1.97.0 or newer.

Ondine CLI does not need Node.js, npm, or WebAssembly at runtime.

*** Prebuilt binary

Install the latest Linux ~x86_64~ binary with the installer:

#+begin_src sh
curl -fsSL https://raw.githubusercontent.com/gicrisf/ondine-cli/main/install.sh | bash
#+end_src

This installs to =~/.local/bin=. Set ~ONDINE_INSTALL_DIR~ to choose another directory, or ~ONDINE_VERSION~ to pin a release. Manual downloads are available from the [[https://github.com/gicrisf/ondine-cli/releases][releases page]].

*** Cargo

#+begin_src sh
cargo install --git https://github.com/gicrisf/ondine-cli --locked --bin ondine
#+end_src

The build uses the compiler revision pinned in ~Cargo.lock~.

*** Nix

#+begin_src sh
# Runs the command without installing it
nix run github:gicrisf/ondine-cli -- flow.mmd

# Builds the package
nix build

# Enters a development shell
nix develop
#+end_src

*** Verify

#+begin_src sh
ondine --version
#+end_src

Continue with [[/projects/ondine-cli/getting-started/quick-start/][Quick Start]] or [[/projects/ondine-cli/getting-started/usage/][Usage]].

#+begin_description
Render diagrams and transform Markdown fences with the ondine command.
#+end_description

*** Render diagrams

Render a ~.mmd~ or ~.mermaid~ file beside its source:

#+begin_src sh
ondine flow.mmd
#+end_src

Render every SVG into one directory:

#+begin_src sh
ondine diagrams/*.mmd --out-dir public/diagrams
#+end_src

Render standard input to standard output:

#+begin_src sh
cat flow.mmd | ondine > flow.svg
#+end_src

Print diagrams as ASCII text:

#+begin_src sh
ondine --ascii flow.mmd
#+end_src

With multiple files, ASCII output is concatenated in argument order. ~--out-dir~ is ignored in ASCII mode.

**** Render options

| Option | Meaning |
|--------+---------|
| ~-a~, ~--ascii~ | Print diagrams as ASCII text instead of writing SVG files. |
| ~-o~, ~--out-dir <DIR>~ | Write every rendered SVG into one directory. |
| ~-h~, ~--help~ | Print usage. |
| ~-V~, ~--version~ | Print the version. |

Files named ~.mmd~ or ~.mermaid~ replace that suffix with ~.svg~. Other names keep their extension, so ~flow.txt~ becomes ~flow.txt.svg~.

*** Transform Markdown fences

Transform a Markdown tree into a separate output tree:

#+begin_src sh
ondine markdown content --out-dir build/content
#+end_src

The source files are not modified. Directory inputs mirror their relative paths under the output directory.

Check that generated Markdown is current:

#+begin_src sh
ondine markdown content --out-dir build/content --check
#+end_src

Write one transformed file to standard output:

#+begin_src sh
ondine markdown page.md --stdout
#+end_src

~--check~ writes nothing and exits with status 1 when output is missing or stale. It requires an existing ~--out-dir~. ~--stdout~ accepts exactly one Markdown file.

**** Markdown options

| Option | Meaning |
|--------+---------|
| ~-o~, ~--out-dir <DIR>~ | Write transformed Markdown to a separate tree. |
| ~--check~ | Write nothing, and exit with 1 when output is missing or out of date. |
| ~--stdout~ | Write one transformed Markdown file to standard output. |
| ~-h~, ~--help~ | Print usage. |

Unlike render ~--out-dir~, which collects SVG files into one directory, Markdown ~--out-dir~ preserves the input directory structure.

Only fences tagged ~mermaid~ are transformed. See [[/projects/ondine-cli/reference/markdown-fences/][Markdown Fences]] for fence syntax, output shape, and accessibility. See [[/projects/ondine-cli/reference/output-and-errors/][Output and Errors]] for diagnostics and exit behavior.

** Markdown Fences

#+begin_description
Transform fenced Mermaid blocks into inline SVG without editing the source.
#+end_description

*** What gets transformed

A fenced code block tagged ~mermaid~ is replaced with inline SVG:

#+begin_src markdown
```mermaid
flowchart LR
  A --> B
```
#+end_src

The generated Markdown contains:

#+begin_src html
<div class="mermaid-diagram">
  <svg ...>...</svg>
</div>
#+end_src

The transformer handles backtick and tilde fences, indented fences, and multiple diagrams in one file. Fences in other languages are left untouched. An unclosed fence is also left unchanged.

*** Source files stay untouched

Use ~--out-dir~ to write the transformed Markdown into a separate tree:

#+begin_src sh
ondine markdown content --out-dir build/content
#+end_src

Directory inputs mirror their relative paths under the output directory. For example, ~content/posts/example.md~ becomes ~build/content/posts/example.md~.

The command writes Markdown only. Copy non-Markdown files from the source tree separately if your site needs colocated assets.

*** Check generated output

#+begin_src sh
ondine markdown content --out-dir build/content --check
#+end_src

~--check~ writes nothing. It exits with status 1 when a generated file is missing or stale, which makes it suitable for CI. The output directory must already exist.

*** Write one file to stdout

#+begin_src sh
ondine markdown page.md --stdout
#+end_src

~--stdout~ accepts exactly one Markdown file and writes the transformed Markdown to standard output.

*** IDs and accessibility

Ondine emits fixed ~ondine-title~ and ~ondine-desc~ IDs when the diagram source defines an accessibility title or description. The transformer namespaces those IDs per diagram, so multiple diagrams can share one page without collisions.

Use Mermaid's ~accTitle~ and ~accDescr~ directives in the fence:

#+begin_src markdown
```mermaid
flowchart LR
  accTitle: Build pipeline
  accDescr: Source is compiled to inline SVG.
  A --> B
```
#+end_src

There is no separate alt or caption metadata syntax. The fence source and the generated SVG carry the accessible information.

*** Static site example

A typical static-site pipeline is:

#+begin_src sh
ondine markdown content --out-dir build/content
#+end_src

Build the site from ~build/content~, or use the same directory as the content root of your generator. Keep the original ~content~ tree as the source of truth.

#+begin_description
File naming, diagnostics, exit codes, and compiler revision details.
#+end_description

*** Render output

~.mmd~ and ~.mermaid~ sources replace their suffix with ~.svg~:

#+begin_src text
flow.mmd      -> flow.svg
flow.mermaid  -> flow.svg
#+end_src

Other names keep their extension:

#+begin_src text
flow.txt      -> flow.txt.svg
#+end_src

Without ~--out-dir~, the SVG is written beside the source. With ~--out-dir~, every SVG is written into that directory. In ASCII mode, output goes to standard output instead.

*** Markdown output

~ondine markdown~ writes only Markdown files. Directory inputs preserve their relative structure under ~--out-dir~.

A file with a failing Mermaid fence is not written. Other input files are still processed, and the command exits with status 1.

*** Diagnostics

Compiler errors use this format:

#+begin_src text
source:line:column: message
#+end_src

Errors without a position use:

#+begin_src text
source: message
#+end_src

For Markdown fences, line and column numbers are adjusted to the Markdown file. The opening fence line is the reference for the diagram source.

*** ~--check~ failures

When generated Markdown is missing or stale, ~--check~ prints:

#+begin_src text
path/to/output.md is out of date
#+end_src

It writes nothing and exits with status 1.

*** Exit status

The command exits with status 1 when any file fails to render or when ~--check~ finds stale output. It exits with status 0 when every requested operation succeeds.

Unclosed fences and non-Mermaid fences are copied unchanged, not reported as errors.

*** Compiler revision

The compiler crate is pinned to a commit in ~wevm/ondine~ rather than a crates.io release. Update the ~rev~ in ~Cargo.toml~ deliberately, then run the test suite.

Ondine CLI makes no network requests. The release binary needs no Node.js, npm, or WebAssembly runtime.
